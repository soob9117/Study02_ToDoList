## 1. 개요

### 1.1 목적
하루 10~20개의 할 일을 날짜별로 관리하는 개인용 웹 앱. 브라우저에서 `index.html`을 더블클릭하면 바로 실행되고, 새로고침해도 데이터가 유지된다.

### 1.2 사용자
1인 사용자. 로그인, 동기화, 공유 기능 없음.

### 1.3 범위

| 포함 | 제외 |
|---|---|
| 할 일 추가·수정·삭제, 완료 체크 | 사용자 정의 카테고리 |
| 카테고리 3종(업무/개인/공부) 분류·필터 | 마감 시간, 우선순위, 알림 |
| 날짜별 관리, 날짜 이동 | 기기 간 동기화, 서버 저장 |
| 오늘 이전 미완료 항목 수동 이월 | 반복 할 일 |
| 날짜별 전체·카테고리별 진행률 | 기간별 통계·차트 |
| JSON 내보내기·가져오기, 백업 복원 | 드래그로 순서 변경 |

## 2. 기술 제약

- 순수 HTML/CSS/JavaScript. 외부 라이브러리와 빌드 도구는 쓰지 않는다.
- ES 모듈(`import`/`export`)은 쓰지 않는다. 모든 스크립트는 일반 `<script src>`로 순서대로 불러온다.
- `index.html`과 `tests.html` 모두 더블클릭(`file://`)으로 동작해야 한다.
- 데이터는 브라우저 `localStorage`에 저장한다.
- 데스크톱 우선이지만 360px 폭 모바일에서도 사용할 수 있어야 한다.

## 3. 파일 구조

```
index.html          앱 화면 마크업, 스크립트 로드
style.css           전체 스타일 (반응형 포함)
js/dates.js         로컬 기준 날짜 유틸 (DOM 모름)
js/storage.js       localStorage 읽기/쓰기, 데이터 형식 검증, 백업 (DOM 모름)
js/todos.js         할 일 로직: CRUD, 완료, 이월, 진행률 (DOM 모름)
js/render.js        상태 → 화면 그리기
js/app.js           초기화, 이벤트 연결, 상태 관리
tests.html          테스트 실행 페이지 (더블클릭으로 열면 결과 표시)
js/tests.js         테스트 코드와 작은 assert 헬퍼
```

### 3.1 스크립트 로드와 전역 이름

- 전역 객체 하나 `window.TodoApp`만 만든다. 각 파일이 `TodoApp.Dates`, `TodoApp.Storage`, `TodoApp.Todos`, `TodoApp.Render`, `TodoApp.App`을 하나씩 등록한다.
- 로드 순서: `dates.js` → `storage.js` → `todos.js` → `render.js` → `app.js`. `tests.html`은 같은 순서로 불러온 뒤 `tests.js`를 불러온다.
- `index.html` 마지막에서 `TodoApp.App.init({ root, storage: window.localStorage })`로 시작한다.

### 3.2 파일 내부 구성

각 JS 파일 안에서 역할별로 구역을 나누고 주석으로 구분한다. 예:

```js
// ============================================================
// 상수
// ============================================================

// ============================================================
// 날짜 문자열 변환
// ============================================================
```

## 4. 데이터

### 4.1 할 일 항목

```js
{
  id: "t_1727830000000_x7k2",  // 생성 시각 + 랜덤 문자열
  text: "보고서 초안 작성",      // 앞뒤 공백 제거 후 1~100자
  category: "work",           // "work" | "personal" | "study"
  done: false,
  date: "2026-10-02",         // 현재 속한 날짜 (로컬 기준 YYYY-MM-DD)
  originalDate: "2026-10-02", // 처음 등록한 날짜 (로컬 기준 YYYY-MM-DD), 이후 변경 없음
  createdAt: 1727830000000    // 생성 시각 (ms)
}
```

카테고리 표시명: `work` → 업무, `personal` → 개인, `study` → 공부.

### 4.2 저장 형식

| 키 | 값 |
|---|---|
| `todoApp.v1` | `{ "version": 1, "todos": [ ... ] }` JSON 문자열 |
| `todoApp.v1.backup` | 덮어쓰기 직전의 데이터 원문 문자열 (없을 수 있음) |

- 상태가 바뀔 때마다(추가·수정·삭제·완료·이월·가져오기·복원) 즉시 저장한다.
- 예상 용량: 하루 20개 × 1년 ≈ 7,000개, 약 1~2MB. localStorage 한도(약 5MB) 안에 들어간다.

### 4.3 날짜 처리 규칙

- **`toISOString()`은 쓰지 않는다.** UTC 기준이라 한국에서는 오전 9시 전에 날짜가 하루 밀린다.
- `toLocalDateStr(d)`: `getFullYear()`, `getMonth() + 1`, `getDate()`로 `YYYY-MM-DD`를 만든다(두 자리 0 채움).
- `parseLocalDate(str)`: `new Date(y, m - 1, d)`로 로컬 자정 `Date`를 만든다. 변환 결과의 연·월·일이 입력과 다르면(예: `2026-02-30`) 유효하지 않은 날짜로 본다.
- 날짜 더하기와 차이 계산은 `parseLocalDate` 결과로 하고, 차이는 `Math.round(ms / 86400000)`으로 일 단위로 반올림한다.
- 요일은 하드코딩하지 않는다. `parseLocalDate(str).getDay()`로 `["일","월","화","수","목","금","토"]`에서 찾는다.
- 날짜 순서는 `YYYY-MM-DD` 문자열 비교로 판단한다.
- "오늘"은 렌더링할 때마다 계산한다. 앱을 열어둔 채 자정이 지나도 창에 다시 포커스가 오면(`visibilitychange`/`focus`) 오늘 기준을 다시 계산해 그린다.

## 5. 기능 요구사항

### 5.1 날짜 이동
- 상단에 `◀ 2026-10-02 (금) · 오늘 ▶ [오늘]`을 표시한다. 요일은 계산한 값이다.
- ◀/▶는 하루 전/후로 이동하고, [오늘]은 오늘로 돌아온다. 보고 있는 날짜가 오늘일 때만 "· 오늘" 표시를 붙인다.
- 과거·미래 날짜에서도 추가·수정·삭제·완료를 모두 쓸 수 있다.
- 앱을 열면 항상 오늘 날짜에서 시작한다.

### 5.2 할 일 추가
- 입력란 + 카테고리 선택 + [추가] 버튼. Enter 또는 [추가]로 추가한다.
- 앞뒤 공백을 제거한 결과가 비어 있으면 추가하지 않는다. 입력란은 `maxlength="100"`으로 100자 초과를 막는다.
- 새 항목의 `date`와 `originalDate`는 보고 있는 날짜다.
- 추가 후 입력란을 비우고 포커스를 유지한다. 카테고리는 마지막으로 고른 값을 유지한다.
- **한글 입력**: `keydown`에서 `e.isComposing === true`이거나 `e.keyCode === 229`이면 무시한다. 조합 중 Enter로 중복 추가되거나 마지막 글자가 잘리지 않게 하기 위해서다.

### 5.3 할 일 수정
- ✎ 버튼으로 수정 모드에 들어간다. 텍스트 입력란과 카테고리 선택이 나타난다. **✎ 버튼만으로 텍스트와 카테고리 수정이 모두 가능해야 한다**(터치 기기 대응).
- 데스크톱에서는 텍스트 더블클릭으로도 수정 모드에 들어갈 수 있다(보조 수단).
- Enter 또는 포커스 이탈(blur)이면 저장하고 Esc면 취소한다. 텍스트가 비어 있으면 저장하지 않고 원래 값으로 되돌린다.
- **한글 입력**: 수정 입력란에도 5.2의 IME 규칙을 똑같이 적용한다.
- **Esc/Enter와 blur 충돌 방지**: 수정 모드를 시작할 때 `finished = false` 플래그를 만든다. Enter·Esc·blur 중 먼저 처리된 쪽이 `finished = true`로 바꾸고, 이후 이벤트는 무시한다.
  - Esc 후 뒤따르는 blur → 저장하지 않음
  - Enter 후 뒤따르는 blur → 두 번째 저장 없음 (저장은 정확히 1회)
- 같은 입력란 안에서 카테고리 선택으로 포커스가 옮겨갈 때는 blur로 저장하지 않는다. 포커스가 수정 영역 밖으로 나갈 때만 저장한다.
- **수정 중 다른 항목 클릭**: A를 수정하는 중에 다른 항목 B의 ✎·체크박스·🗑를 누르면 **한 번에** 동작해야 한다(A 저장 → B 동작).
  - 수정 중에는 `root`의 `mousedown`에서 수정 영역 밖의 `[data-action]` 대상에 `preventDefault()`를 한다. 그러면 포커스가 수정 입력란에 남아 blur 저장과 목록 다시 그리기가 클릭 전에 일어나지 않는다.
  - 클릭 처리에서는 열린 수정을 먼저 저장해 끝낸 뒤 해당 동작을 실행한다.
  - 완료 토글은 `change`가 아니라 `click`으로 처리한다. 다시 그리기로 DOM에서 빠진 체크박스의 `change`는 `root`까지 전달되지 않기 때문이다.
  - 동작 대상이 아니거나 수정 영역 안의 요소에는 `preventDefault()`를 하지 않는다.

### 5.4 할 일 삭제
- 🗑 버튼을 누르면 `confirm("'보고서 초안 작성'을(를) 삭제할까요?")`로 확인한 뒤 삭제한다.

### 5.5 완료 체크
- 체크박스로 완료를 토글한다.
- 완료 항목은 취소선과 흐린 색으로 표시한다.
- 정렬: 미완료가 위, 완료가 아래. 각 그룹 안에서는 `createdAt` 오름차순.

### 5.6 카테고리 필터
- 필터: (전체) / 업무 / 개인 / 공부. 목록 표시만 거른다.
- 진행률은 필터와 관계없이 항상 그 날짜 전체 기준이다.

### 5.7 진행률
- 보고 있는 날짜 기준으로 `진행률 8/12 (67%)` 텍스트와 진행 막대를 표시한다.
- 그 아래 `업무 3/5 · 개인 2/3 · 공부 3/4`처럼 카테고리별 완료/전체를 표시한다.
- 백분율은 `Math.round(완료 / 전체 × 100)`이다. 전체가 0이면 0%로 표시한다(NaN 금지).

### 5.8 미완료 이월
- 대상: `date < 오늘 && done === false`인 **모든** 항목. 중간에 기록이 없는 날이 있어도 예전 미완료가 빠지지 않는다.
- 보고 있는 날짜가 오늘이고 대상이 1개 이상일 때만 `[밀린 미완료 N개 가져오기]` 버튼을 보여준다.
- 누르면 대상 항목의 `date`만 오늘로 바꾼다(이동). `originalDate`는 바꾸지 않는다.
- 이월된 항목(`date !== originalDate`)에는 `N일째` 표시를 붙인다. `N = (date − originalDate)일 + 1`. 예: originalDate 09-30, date 10-02 → "3일째".
- 미래 날짜 항목은 대상이 아니다.

### 5.9 JSON 내보내기
- `[JSON 내보내기]`를 누르면 현재 저장 형식(`{ version: 1, todos }`) 그대로 `todo-backup-YYYY-MM-DD.json`(오늘 날짜)로 다운로드한다.
- 구현: `Blob` + `URL.createObjectURL` + `<a download>`. `file://`에서도 동작한다.

### 5.10 JSON 가져오기
1. `[JSON 가져오기]`를 누르면 숨겨진 `<input type="file" accept=".json,application/json">`로 파일을 고른다. `FileReader`로 읽는다.
2. **검증** (`Storage.validateData`): 하나라도 실패하면 첫 오류를 `alert`로 보여주고 데이터는 바꾸지 않는다.
   - JSON 파싱 가능
   - 최상위가 객체이고 `version === 1`
   - `todos`가 배열
   - 각 항목:
     - `id`: 비어 있지 않은 문자열, 전체에서 중복 없음
     - `text`: 문자열, 앞뒤 공백 제거 후 1~100자
     - `category`: `work`/`personal`/`study` 중 하나
     - `done`: 불리언
     - `date`, `originalDate`: `YYYY-MM-DD` 형식이고 실제 존재하는 날짜, `originalDate <= date`
     - `createdAt`: 유한한 숫자
   - 오류 메시지 예: `3번째 항목: category 값이 잘못되었습니다.`
3. **확인**: `confirm("현재 할 일 A개가 가져온 B개로 대체됩니다. 계속할까요?")`
4. **승인 시**: 현재 데이터 원문을 `todoApp.v1.backup`에 저장한 뒤 가져온 데이터로 덮어쓰고 다시 그린다.
5. 같은 파일을 다시 고를 수 있도록 처리 후 file input의 값을 비운다.

### 5.11 백업 복원
- `todoApp.v1.backup`에 값이 있을 때만 `[백업 복원]` 버튼을 보여준다.
- 누르면:
  1. 백업 원문을 `validateData`로 검증한다. 실패하면 `alert("백업 데이터가 손상되어 복원할 수 없습니다.")`를 띄우고 아무것도 바꾸지 않는다.
  2. `confirm("현재 할 일 A개를 백업의 B개로 되돌립니다. 계속할까요?")`로 확인한다.
  3. 승인하면 현재 데이터와 백업을 **맞바꾼다**. 현재 데이터 원문은 백업 키로, 백업은 본 데이터로 간다. 그래서 복원도 한 번 되돌릴 수 있다.
- 백업은 1개만 유지한다. 새 백업이 생기면 이전 백업을 덮어쓴다.

### 5.12 저장 오류 처리
- **불러오기 실패**: `todoApp.v1`이 JSON 파싱이나 검증에 실패하면 원문을 `todoApp.v1.backup`에 보관하고 빈 목록으로 시작한다. 화면 상단에 "저장된 데이터를 읽을 수 없어 백업으로 보관하고 새로 시작합니다." 안내를 표시한다.
- **저장 실패**: `setItem`이 예외를 던지면(용량 초과, 저장 차단 등) 화면 상단에 "저장에 실패했습니다. 새로고침하면 변경 내용이 사라질 수 있습니다." 경고를 표시한다. 화면 상태는 유지하고, 다음 저장이 성공하면 경고를 지운다.
- 저장소 접근 자체가 예외를 던지는 환경에서도 앱이 멈추지 않는다. 모든 읽기/쓰기를 `try/catch`로 감싼다.

### 5.13 빈 상태
- 보고 있는 날짜에 할 일이 없으면 "이 날짜에 할 일이 없습니다."를 표시한다.
- 할 일은 있지만 필터 결과가 없으면 "이 카테고리에 할 일이 없습니다."를 표시한다.

### 5.14 다른 탭 변경 감지
- 같은 브라우저에서 앱을 탭 두 개 이상으로 열 수 있다(`index.html`을 다시 더블클릭하는 경우 등). 한 탭의 저장이 다른 탭의 변경을 조용히 덮어쓰지 않도록 `window`의 `storage` 이벤트를 듣는다.
- `event.key`가 `todoApp.v1`이면:
  1. 열려 있는 수정은 **저장하지 않고** 닫는다(저장하면 다른 탭의 변경을 다시 덮어쓰게 된다).
  2. `Storage.load`로 다시 불러와 화면을 갱신한다.
  3. 화면 상단에 "다른 탭에서 변경된 내용을 불러왔습니다." 안내를 표시한다.
  4. 이 처리에서는 저장소에 쓰지 않는다.
- `event.key`가 `todoApp.v1.backup`이면 [백업 복원] 버튼 표시 여부만 갱신하고 안내는 띄우지 않는다. 그 외 키는 무시한다.
- 리스너는 앱 정리(`destroy`) 때 제거한다.

## 7. 모듈 인터페이스

DOM에 의존하지 않는 모듈(`Dates`, `Storage`, `Todos`)은 순수 함수 위주로 만들어 `tests.html`에서 직접 검증한다.

| 모듈 | 주요 함수 |
|---|---|
| `TodoApp.Dates` | `toLocalDateStr(date)`, `parseLocalDate(str)`, `isValidDateStr(str)`, `addDays(str, n)`, `diffDays(a, b)`, `weekdayLabel(str)` |
| `TodoApp.Storage` | `load(storage)` → `{ data, error }`, `save(storage, data)` → `boolean`, `validateData(obj)` → `{ ok, error }`, `parseAndValidate(text)`, `hasBackup(storage)`, `writeBackup(storage, raw)`, `restoreBackup(storage)` |
| `TodoApp.Todos` | `createTodo(text, category, dateStr, now)`, `addTodo`, `updateTodo`, `deleteTodo`, `toggleTodo`, `todosForDate`, `sortTodos`, `overdueTodos(todos, today)`, `carryOver(todos, today)`, `progress(todos, dateStr)`, `carryDays(todo)` |
| `TodoApp.Render` | `render(root, state)` |
| `TodoApp.App` | `init({ root, storage, today })`. `today`는 테스트에서 날짜를 고정하려고 주입하는 함수로, 기본값은 `() => toLocalDateStr(new Date())` |

- `Todos` 함수는 원본 배열을 바꾸지 않고 새 배열을 반환한다.
- `Storage` 함수는 저장소 객체(`getItem`/`setItem`/`removeItem`)를 인자로 받는다. 테스트는 메모리 기반 가짜 저장소를 쓰므로 실제 데이터를 건드리지 않는다.

## 9. 설계 결정 기록

설계 과정에서 검토한 선택지와 채택 이유를 남긴다.

### 9.1 할 일을 다루는 단위
| 선택지 | 내용 | 결과 |
|---|---|---|
| **날짜별 관리** | 할 일이 날짜에 속함, 날짜 이동으로 기록 열람 | **채택** |
| 단일 목록 | 날짜 구분 없이 하나의 목록 | 기각: "매일" 관리 흐름과 기록 열람이 어려움 |
| 단일 목록 + 매일 자동 초기화 | 날짜가 바뀌면 완료 항목 정리 | 기각: 기록이 남지 않음 |

### 9.2 미완료 이월
| 선택지 | 결과 |
|---|---|
| **수동 이월 (버튼)** | **채택**: 사용자가 가져올지 결정 |
| 자동 이월 | 기각: 미완료가 쌓여 하루 10~20개 규모를 넘기 쉬움 |
| 이월 없음 | 기각: 매번 다시 입력해야 함 |

세부 결정:
- **이동 방식 + `originalDate`**: 복사 대신 `date`만 바꿔 중복을 막는다. `originalDate`로 처음 등록일을 보존하고, "N일째"로 얼마나 밀렸는지 보여준다.
- **대상은 "오늘 이전의 모든 미완료"**: "직전에 기록이 있는 날짜"만 보면 하루 건너뛰었을 때 예전 미완료가 묻힌다.

### 9.3 진행률 범위
| 선택지 | 결과 |
|---|---|
| **날짜별 전체 + 카테고리별** | **채택** |
| 전체만 | 기각: 카테고리 분류의 의미가 줄어듦 |
| + 최근 7일 추이 차트 | 기각: 화면과 구현 증가 대비 이득 작음 (YAGNI) |

### 9.4 코드 구조
| 선택지 | 결과 |
|---|---|
| **역할별 스크립트 분리 + 일반 `<script src>`** | **채택**: `file://` 동작, 로직/화면 분리로 테스트 용이, 파일마다 역할 하나 |
| 단일 `app.js` | 기각: 로직과 DOM이 섞여 테스트가 어렵고 파일이 커짐 |

### 9.5 기타 결정
- **카테고리 3종 고정**: 사용자 정의 카테고리는 범위에서 뺐다 (YAGNI).
- **날짜는 로컬 기준으로 직접 생성**: `toISOString()`은 UTC라 한국에서 오전 9시 전에 날짜가 하루 밀린다.
- **요일은 계산**: 하드코딩하면 틀린다(초안에서 2026-10-02를 목요일로 잘못 적은 사례가 있음, 실제는 금요일).
- **IME 조합 중 Enter 무시**: 한글 조합 중 Enter로 중복 추가되거나 마지막 글자가 잘리는 문제를 막는다.
- **수정 모드 `finished` 플래그**: Esc/Enter 뒤에 따라오는 blur 때문에 원치 않는 저장이나 이중 저장이 생기는 것을 막는다.
- **전체 다시 그리기**: 하루 20개 규모라 성능 문제가 없고 코드가 단순해진다.
- **가져오기 시 덮어쓰기 + 확인 + 자동 백업**: 병합 규칙의 복잡도를 피하고, 실수로 덮어써도 백업으로 되돌릴 수 있게 한다.
- **백업 복원은 맞바꾸기**: 복원도 한 번 되돌릴 수 있다. 대신 복원 뒤에도 [백업 복원] 버튼이 계속 보인다(승인됨).
- **가져오기 검증에 `originalDate <= date`**: 이월은 날짜를 앞으로만 옮기므로 정상 데이터라면 항상 성립한다(승인됨).
- **자정 처리**: 창이 다시 활성화될 때 "오늘"을 다시 계산한다(승인됨).
- **`textContent`만 사용**: 사용자 입력이 HTML로 해석되지 않게 한다(승인됨).
- **수정 중 카테고리 선택은 저장 트리거가 아님**: 포커스가 수정 영역 밖으로 나갈 때만 저장한다(승인됨).
- **모바일**: 데스크톱 우선을 유지하되 viewport 메타, 44px 터치 대상, 16px 이상 입력 글자, ✎만으로 전체 수정 가능, 360px에서 입력 줄 줄바꿈을 지원한다.

### 9.6 구현 후 최종 리뷰에서 추가한 결정
초기 설계에는 없었지만, 구현을 마친 뒤 브랜치 전체를 리뷰하면서 발견한 문제를 해결하려고 추가했다.

- **수정 중 다른 항목 클릭 처리(5.3)**
  - 발견한 문제: A를 수정하는 중에 B의 버튼을 누르면 `mousedown`이 포커스를 옮겨 blur 저장이 일어났다. 이때 목록 전체를 다시 그리면서 B의 버튼이 `mouseup` 전에 DOM에서 빠져 클릭 자체가 사라졌다. 실제 Chrome 마우스 이벤트로 재현했다. 그 결과 ✎는 두 번 눌러야 했고 체크박스는 토글되지 않았다. 터치도 같은 순서로 이벤트가 발생해 영향을 받는다.
  - 자동 테스트가 놓친 이유: 테스트는 숨겨진 컨테이너에서 합성 이벤트를 쓰기 때문에 실제 포커스 이동 순서를 재현하지 못했다.
  - 선택: `mousedown`에서 포커스 이동을 막고, 클릭 처리에서 저장 후 동작한다. "전체 다시 그리기"(9.5)를 유지하면서 문제만 막는 가장 작은 변경이다. 부분 갱신으로 바꾸는 방안은 구조 변경이 커서 택하지 않았다.
- **다른 탭 변경 감지(5.14)**
  - 발견한 문제: 저장은 메모리의 전체 목록을 통째로 쓰는 방식이다. 탭 두 개에서 각각 수정하면 나중에 저장한 탭이 앞의 변경을 경고 없이 지운다. 원래 1인·단일 사용을 전제로 해서 범위에 없었지만, `index.html`을 다시 더블클릭하는 것만으로 쉽게 생기는 데이터 손실 경로다.
  - 선택: `storage` 이벤트로 다시 불러오고 안내한다. 탭 간 병합이나 잠금은 복잡도에 비해 이득이 작아 택하지 않았다(YAGNI).
  - 열린 수정을 저장하지 않고 닫는 이유: 그 수정을 저장하면 방금 불러온 다른 탭의 변경을 다시 덮어쓰기 때문이다. 대가로 수정 중이던 입력 내용 하나를 잃을 수 있다.
