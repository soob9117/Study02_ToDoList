## 1. 사용자 요청 원문 요약

1. **넓은 화면 레이아웃**: 약 900px 이상에서는 2단으로 나눈다. 왼쪽에 입력란·필터·할 일 목록, 오른쪽에 진행률과 캘린더를 둔다. 좁은 화면은 한 줄로 쌓고 캘린더를 맨 아래에 둔다. 360px에서도 깨지면 안 된다.
2. **JSON 메뉴**: 맨 아래 [JSON 내보내기]·[JSON 가져오기]를 없애고, 위쪽에 [JSON] 버튼을 둔다. 누르면 내보내기·가져오기(백업이 있으면 백업 복원도)가 펼쳐진다. 다시 누르거나 바깥을 누르면 닫힌다.
3. **완료한 것 지우기**: 원래 JSON 버튼 자리에 둔다. 보고 있는 날짜의 완료 항목만 지운다. 확인 문구는 "완료한 할 일 N개를 삭제할까요?"이다. 완료 항목이 없으면 버튼을 비활성화한다.
4. **월간 캘린더**: 보고 있는 날짜가 속한 달을 일~토 7칸으로 보여준다. 이전/다음 달 버튼이 있다. 날짜 칸을 누르면 그 날짜의 목록으로 이동한다. 오늘과 선택한 날짜를 구분해서 표시한다. ◀ ▶ [오늘]로 날짜를 바꾸면 캘린더도 따라간다.
5. **날짜 스티커**: 날짜 칸 오른쪽 위에 1개를 붙인다. ⭐ ❤️ 🔥 ✅ ❗ 중에서 고르고, 없앨 수도 있다.
6. **날짜 메모**: 날짜 숫자 아래에 짧은 제목을 적는다(최대 10자). 칸보다 길면 말줄임(…)으로 표시한다.
7. **편집 방법**: 날짜 클릭은 이동에 쓰므로, 캘린더 바로 아래에 "선택한 날짜"의 스티커 선택과 메모 입력란을 둔다. 터치 화면에서도 쓸 수 있어야 한다. 메모 입력란에도 한글 입력 중 Enter 처리(isComposing)를 적용한다.
8. **데이터**: 스티커·메모는 할 일과 별도로 날짜별로 저장한다. 형식이 바뀌면 version을 올리고, 기존 v1 데이터는 자동으로 변환해서 할 일이 사라지지 않게 한다. 내보내기에 스티커·메모를 포함하고, 가져오기는 예전 v1 파일도 받는다. 검증 규칙도 새 필드에 맞게 넣는다.

## 3. 섹션 1: 화면 레이아웃 (사용자 수정 요청 반영본)

### 3.1 넓은 화면 (900px 이상): 2단

```
┌──────────────────────────────────────────────────────────────────┐
│ ◀   2026-10-02 (금) · 오늘   ▶  [오늘]                  [JSON ▾]  │  ← 머리글(전체 폭)
│                                                ┌──────────┐      │
│ (안내·경고 메시지, 필요할 때만, 전체 폭)        │ 내보내기  │      │  ← JSON 메뉴
│                                                │ 가져오기  │      │    (백업 복원은
├───────────────────────────────────┬────────────│ 백업 복원 │──────┤     백업 있을 때만)
│ [밀린 미완료 N개 가져오기]         │ 진행률 1/3 └──────────┘      │
│ [할 일 입력........] [업무▾][추가] │ ████░░░░░░░░                  │

│ ☐ [업무] 채점            ✎ 🗑     ├───────────────────────────────┤
│ ☑ [공부] 파이썬 프로그래밍 ✎ 🗑   │ ‹      2026년 10월      ›      │
│                                   │ 일 월 화 수 목 금 토           │
│ [완료한 것 지우기]                │ (6주 × 7칸 달력)               │
│                                   ├───────────────────────────────┤
```

### 3.3 캘린더 칸 규칙: 6주 전체가 잘리지 않게

- 열은 `grid-template-columns: repeat(7, minmax(0, 1fr))`다. 칸 폭이 캘린더 폭에 맞춰 줄어들고 가로로 넘치지 않는다.
- 항상 6주(42칸)를 그리고 칸 높이를 46px로 고정한다. 캘린더 안에서 따로 스크롤하지 않고, 달마다 높이가 바뀌지 않는다.
- 칸 크기: 넓은 화면 오른쪽 단(캘린더 폭 약 336px)에서 약 46×46px, 360px 화면(캘린더 폭 약 320px)에서 약 44×46px. 둘 다 터치 기준(44px) 이상이다.
- 칸 안 배치(겹치지 않게):
  - 윗줄 16px: 왼쪽에 날짜 숫자, 오른쪽에 스티커
  - 아랫줄: 메모. `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`로 한 줄 말줄임
  - 칸 자체도 `min-width: 0; overflow: hidden`
- 앞뒤 달의 날짜는 흐리게 표시하고, 눌러도 그 날짜로 이동한다.
- 오늘·선택한 날짜 구분:
  - 선택한 날짜(보고 있는 날짜): 파란 테두리와 연한 파란 채움, `aria-selected="true"`
  - 오늘: 주황 테두리와 굵은 숫자, `aria-current="date"`
  - 둘이 같은 날이면 두 표시를 함께 쓴다. 색만으로 구분하지 않는다.
- JSON 메뉴는 버튼 바로 아래에 펼쳐지는 작은 메뉴다. 버튼을 다시 누르거나, 바깥을 누르거나, Esc를 누르면 닫힌다.

## 4. 섹션 2: 데이터 형식과 v1 → v2 변환 (초안, 승인 대기)

### 4.1 저장 형식 v2

키는 그대로 `todoApp.v1`이다. 키 이름을 바꾸면 기존 사용자 데이터를 찾지 못할 위험이 있어서, 형식 구분은 `version`으로만 한다.

```js
{
  version: 2,
  todos: [ /* v1과 동일한 할 일 항목 */ ],
  days: {
    "2026-10-02": { sticker: "⭐", memo: "발표 준비" },
    "2026-10-05": { sticker: "❤️" },
    "2026-10-13": { memo: "시험 공부" }
  }
}
```

- 스티커: `⭐ ❤️ 🔥 ✅ ❗` 다섯 문자열 중 하나만 허용한다(상수 `STICKERS`). ❤️는 변형 선택자를 포함한 `"❤️"`로 정확히 비교한다.
- 메모: 앞뒤 공백을 제거하고 1~10자다(상수 `MEMO_MAX_LENGTH = 10`). 글자 수는 `Array.from(text).length`로 센다.
- 스티커와 메모를 둘 다 지우면 그 날짜 항목 자체를 지운다(빈 객체를 남기지 않는다).

### 4.2 v1 → v2 자동 변환

- 불러오기, 가져오기, 백업 복원 모두 v1과 v2를 받는다. v1은 기존 규칙으로 검증한 뒤 `{ version: 2, todos, days: {} }`로 바꾼다(`migrate`). 할 일은 그대로 옮겨지므로 잃는 데이터가 없다.
- 앱을 열 때 저장된 데이터가 v1이면 변환한 v2를 바로 저장한다. 그래야 다른 탭과 다음 실행이 같은 형식을 본다.
- 변환은 손실이 없으므로 백업 칸은 건드리지 않는다. 사용자가 만든 백업을 보존하기 위해서다.

### 4.3 검증 규칙 추가

첫 오류에서 멈추고, 다음 문구를 정확히 쓴다.
- `version`이 1 또는 2가 아니면 → "지원하지 않는 version입니다."
- v2에서 `days`가 일반 객체가 아니면 → "days 형식이 잘못되었습니다."
- 날짜 키가 실제 날짜가 아니면 → "days의 2026-02-30: 날짜가 잘못되었습니다."
- `sticker`, `memo` 외의 필드가 있거나, 둘 다 없으면 → "days의 2026-10-02: 형식이 잘못되었습니다."
- 스티커 값이 목록에 없으면 → "days의 2026-10-02: sticker 값이 잘못되었습니다."
- 메모가 문자열이 아니거나 공백 제거 후 1~10자가 아니면 → "days의 2026-10-02: memo 값이 잘못되었습니다."
- 기존 할 일 검증 규칙과 문구는 그대로 둔다.

### 4.4 내보내기·가져오기

- 내보내기 파일은 v2 형식이고 `days`를 포함한다. 파일명은 그대로 `todo-backup-YYYY-MM-DD.json`이다.
- 가져오기 확인 문구: "현재 할 일 A개, 날짜 기록 C일이 가져온 할 일 B개, 날짜 기록 D일로 대체됩니다. 계속할까요?" v1 파일이면 D는 0이다.

### 4.5 모듈 배치

- `Storage`: 형식 상수(`STICKERS`, `MEMO_MAX_LENGTH`), v1/v2 검증, 변환(`migrate`)
- `Days`(새 파일 `js/days.js`, DOM 모름): `setSticker(days, date, sticker | null)`, `setMemo(days, date, text)`, `dayEntry(days, date)`. 원본을 바꾸지 않고 새 객체를 반환한다.
- `Calendar`(새 파일 `js/calendar.js`, DOM 모름): `monthOf(date) → "YYYY-MM"`, `addMonths(month, n)`, `monthGrid(month) → 42개 날짜 문자열`(일요일 시작). 로컬 기준으로 계산하고 `toISOString`은 쓰지 않는다.
- 스크립트 로드 순서(안): `dates → storage → todos → days → calendar → render → app`

## 5. 남은 섹션 (작성 전)

### 섹션 3. 동작 세부: 다룰 내용
- JSON 메뉴 열고 닫기(버튼, 바깥 클릭, Esc). 메뉴 안 항목을 누르면 실행 후 닫는다. 수정 모드와의 상호작용(5.3의 mousedown 처리)을 함께 정한다.
- [완료한 것 지우기]: 보고 있는 날짜의 완료 항목만 지우고, "완료한 할 일 N개를 삭제할까요?"를 확인한다. 0개면 `disabled`.
- 캘린더: 보이는 달 상태(`calendarMonth`), 날짜 칸 클릭 → `viewDate` 변경 + 달 동기화, ◀ ▶ [오늘]·자정 갱신·다른 탭 변경과의 관계
- 스티커 선택: 같은 스티커를 다시 누르면 해제할지, [없음]으로만 해제할지 정한다. 선택 상태는 `aria-pressed`로 표시한다.
- 메모 저장 시점(Enter·blur 저장, Esc 취소 여부), IME(isComposing·keyCode 229) 처리, 수정 모드의 `finished` 플래그 같은 중복 저장 방지
- 날짜 이동 시 편집기 내용 갱신

### 섹션 4. 테스트: 다룰 내용
- `Days`, `Calendar` 순수 함수 테스트(윤년 2월, 1일이 일요일·토요일인 달, 연말·연초 넘김)
- v1 → v2 변환(불러오기·가져오기·백업 복원), v2 검증 오류 문구별 테스트
- 렌더(2단·1단 레이아웃은 수동 확인, 캘린더 42칸·선택·오늘·스티커·메모 말줄임 표시)
- 앱 동작(JSON 메뉴, 완료한 것 지우기, 캘린더 이동, 스티커·메모 편집, 메모 IME)
- 수동 체크리스트(데스크톱 2단, 360px에서 6주가 모두 보이는지, 터치)
